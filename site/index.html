AWS Infrastructure as Code

A website on AWS where every resource is written in Terraform and every change ships through a GitHub Actions pipeline, with no cloud keys stored anywhere.

Jake Moore · Management Information Systems, University of Arizona · Repository on GitHub · Live

The project

Setting up cloud resources by clicking through the AWS console is hard to repeat, leaves no record of who changed what, and usually means long-lived access keys sitting on someone's laptop or in a CI system.

This project does it the way enterprise teams do: the whole stack is Terraform code in one repository. A push to main runs a pipeline that scans the code, logs in to AWS with a short-lived token, shows the planned change, and applies it. The repository is the documentation, the change history and the disaster-recovery plan.

  1. CommitChange a .tf file or the site and push.
  2. ScanCheckov checks the Terraform; any failed check stops the run.
  3. PlanGitHub logs in through OIDC; Terraform shows exactly what will change.
  4. ApplyOn main only, Terraform applies the plan and the site files upload. About 2 minutes end to end.

The Terraform

Two Terraform stacks. bootstrap/ runs once from my machine and creates what the pipeline needs to log in. infra/ is everything else, applied by the pipeline on every push. Each excerpt below is read from the live repository files.

The pipeline

One GitHub Actions workflow, .github/workflows/deploy.yml. Pull requests stop after the plan, so a change can be reviewed before it touches AWS. A second workflow runs terraform plan nightly to confirm AWS still matches the code.
